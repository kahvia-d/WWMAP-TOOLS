# 按文件差量下载（FileArchives）验证记录（2026-09-11）

资源更新系统在整包 ZIP 之外引入按文件差量下载。发布端为包内每个文件生成内容寻址的单文件 ZIP 附件并写入签名清单；客户端安装时优先复用本机已验证文件，只下载缺失或变化的文件。目标场景：大特征包内仅个别文件变化时，避免重新下载整个包。

## 行为设计

- 清单中每个 `ResourcePackage` 增加可选 `fileArchives` 描述：路径、下载地址、大小、SHA-256。字段可缺省，旧程序与既有 schema-v1 清单不受影响；旧客户端忽略该描述，仍按整包 ZIP 下载。
- 附件文件名为 `file-<文件SHA256>-<路径摘要16位>.zip`，ZIP 内仅含该文件一个条目。内容相同但路径不同的文件不会共用附件，避免 ZIP 内条目名错误；`release-report.json` 的 `fileAssets` 按附件字节去重。
- 客户端安装前生成计划：对包内每个文件依次在当前快照、内置资源与 `packages/<id>/<历史版本>` 目录中寻找哈希与大小完全一致的已验证文件并复用；缺失的文件按附件下载。整目录验证通过后才原子提交，事务与回退语义不变。
- 字节未变的包沿用旧包身份与下载地址；未变文件沿用旧发行 URL，发布时只上传新 tag 下的差量附件。内容与旧版本存在归档差异的同 ID 同版本包会被拒绝。
- 清单签名校验扩展到 `fileArchives`：数量必须与文件清单一致、路径校验、URL 校验、大小上下限与哈希格式；目录迁移守卫把归档描述纳入同版本不可变集合。
- 离线导入不使用差量附件，仍验证整包 ZIP；磁盘空间估算改为按需计算（复用文件不占新流量）。
